# 3주차 Step 2 — 모델 비교 결과 (Haiku 4.5 vs Sonnet 5)

작성일: 2026-08-15 / 데이터셋: 홀드아웃 v2 (51건) / 전략: D(few-shot + 카탈로그) 고정

---

## 1. 결과 — 싼 모델이 더 비쌌다

| 모델 | Precision | Recall | F1 | FPR | 캐시적중 | 100건당 비용* |
|---|---|---|---|---|---|---|
| **claude-sonnet-5** | 0.950 | **0.905** | **0.927** | 0.033 | 88% | **665원** |
| claude-haiku-4-5 | 0.909 | 0.476 | 0.625 | 0.033 | **0%** | 790원 |

\* 아래 4장의 비용 계산 수정을 반영한 값

**성능은 Sonnet 이 F1 0.927 vs 0.625 로 압도. 그런데 비용마저 Sonnet 이 더 쌌다.**
토큰 단가는 Haiku 가 절반($1/$5 vs $2/$10)인데도 결과가 뒤집혔다.

### 유형별 재현율

| 유형 | Sonnet 5 | Haiku 4.5 |
|---|---|---|
| hidden_instruction | 5/5 | **2/5** |
| schema_mismatch | 5/5 | **1/5** |
| scope_creep | 4/6 | **2/6** |
| tool_shadowing | 5/5 | **5/5** |

## 2. 발견 ① — Haiku 는 프롬프트 캐싱이 아예 작동하지 않았다

Haiku 의 `cache_read_input_tokens` 가 **51건 전부 0**이었다. 건당 입력 토큰이
4,166 으로, 매 호출마다 system 블록 전체를 새로 계산해 과금됐다.

**원인**: 모델별 최소 캐시 가능 길이 미달.

| 모델 | 최소 캐시 가능 토큰 |
|---|---|
| Claude Haiku 4.5 | **4,096** |
| Claude Sonnet 5 | 1,024 |
| Claude Opus 5 | 512 |

전략 D의 system 블록은 약 **3,490 토큰**이다(Sonnet 의 건당 cache_read 실측값).
Sonnet 기준(1,024)은 넉넉히 넘지만 **Haiku 기준(4,096)에는 미달**한다.

> 최소 길이에 미달하면 캐싱은 **에러 없이 조용히 건너뛰어진다.**
> 로그에도 경고가 남지 않는다. 비용 지표를 직접 보지 않으면 알아챌 수 없다.

**시사점**: "싼 모델로 바꾸면 비용이 준다"는 직관은 캐싱 조건이 동일할 때만 성립한다.
토큰 단가만 비교하고 캐싱 적격 여부를 확인하지 않으면 **비용이 오히려 늘 수 있다.**

**개선 여지**: system 블록을 4,096 토큰 이상으로 늘리면 Haiku 도 캐싱이 켜진다.
그 경우 51건 비용은 403원 → 약 **175원**으로 떨어진다(실측 토큰 기반 추정).
다만 F1 0.625 라는 성능 문제는 그대로다.

## 3. 발견 ② — 카탈로그 대조는 작은 모델도 해낸다, 의미 판별은 못 한다

Haiku 는 거의 모든 유형에서 무너졌는데 **tool_shadowing 만 5/5 로 Sonnet 과 동률**이다.

이유는 두 과제의 성격이 다르기 때문이다.
- **섀도잉 판별**: `safe_list_directory` 를 카탈로그의 `list_directory` 와 대조 →
  본질적으로 **문자열 대조**에 가깝다. 기계적 작업이라 작은 모델도 수행한다.
- **나머지 세 유형**: "이 문장이 정상적인 안내인가, 은폐된 지시인가"를 문맥으로
  가려야 한다. **의미 판별**이며 모델 크기에 민감하다.

→ Step 1의 카탈로그 전략은 **의미 판별 과제를 기계적 대조 과제로 바꿔놓았고**,
   그래서 작은 모델에서도 그 효과가 온전히 살아남았다.
   이는 "입력을 잘 설계하면 모델 요구 수준을 낮출 수 있다"는 일반 원리의 사례다.

## 4. 발견 ③ — 비용 계산 버그 발견 및 정정 (Fixed)

Haiku 가 더 비싸다는 이상한 결과를 추적하다 **자체 비용 계산의 오류 두 가지**를 찾았다.

### 오류 내용

Anthropic usage 필드 정의(공식 문서 확인):
```
총 입력 토큰 = input_tokens + cache_creation_input_tokens + cache_read_input_tokens
```
- `input_tokens` : 캐시되지 않은 토큰. **이미 캐시분이 제외된 값**
- `cache_creation_input_tokens` : 캐시에 쓰는 토큰 → 기본 입력가 **×1.25** (5분 TTL)
- `cache_read_input_tokens` : 캐시에서 읽는 토큰 → 기본 입력가 **×0.1**

| # | 버그 | 영향 |
|---|---|---|
| 1 | `fresh = input_tokens - cache_read` 로 **이중 차감** | 캐시가 잘 듣는 모델의 비용을 과소 보고 |
| 2 | `cache_creation`(×1.25) **완전 누락** | 캐시 생성 비용 미반영 |

캐시가 안 듣던 Haiku 는 우연히 영향을 받지 않아, **비교가 Sonnet 에게만 유리하게
왜곡되어 있었다.** 즉 버그가 없었다면 "Haiku 가 더 비싸다"는 결론이 더 일찍 보였다.

### 정정 결과 (전체 실험 재계산, API 호출 0원)

| 실험 | 캐시적중 | 구버전 | 수정 후 |
|---|---|---|---|
| 2주차 100건 (Sonnet) | 75% | 491원 | **643원** |
| 학습셋 A/B/C | 73~83% | 785원 | **1,027원** |
| 홀드아웃 v1 A/B/C | 74~83% | 772원 | **1,003원** |
| 홀드아웃 v2 A/B/C | 74~84% | 731원 | **952원** |
| 홀드아웃 v2 D | 88% | 269원 | **339원** |
| **누적 합계** | — | **3,317원** | **4,303원** |

**과소 보고분 986원 (30% 상향).** 리포트·발표 자료의 모든 비용 수치를 수정본으로
교체할 것. 재계산 스크립트: `python -m experiments.recompute_costs` (무료).

## 5. 발견 ④ — 캐스케이드가 작동하지 않았다: Haiku 의 확신도는 신뢰할 수 없다

"싼 모델로 1차 판정 → 확신 낮으면 비싼 모델 재검" 파이프라인을 시뮬레이션했다.

| 임계값 | 재검율 | F1 | 비용 |
|---|---|---|---|
| 전부 저가 | 0% | 0.625 | 403원 |
| 0.60 | **0%** | 0.625 | 403원 |
| 0.70 | **0%** | 0.625 | 403원 |
| 0.80 | **0%** | 0.625 | 403원 |
| 0.90 | 8% | 0.625 | 427원 |
| 0.95 | 12% | 0.625 | 439원 |
| 전부 고가 | 100% | 0.927 | 672원 |

**임계값 0.8 까지 재검율이 0%다.** Haiku 가 틀린 판정에도 0.8 이상의 확신도를
부여했기 때문이다. 즉 **Haiku 의 confidence 는 정확도와 상관이 없다(미보정).**

→ 확신도 기반 라우팅은 **값싼 모델의 confidence 가 보정되어 있을 때만** 성립한다.
   이 조합에서는 성립하지 않으므로 캐스케이드를 채택하지 않는다.
→ 대안: 라우팅 기준을 confidence 대신 **규칙 엔진 신호 유무**나
   **도구 위험도(파일/네트워크 접근 여부)** 같은 외부 지표로 삼는 방향.

## 6. 운영 결정

**production 모델: claude-sonnet-5 유지.**

| 근거 | 내용 |
|---|---|
| 성능 | F1 0.927 vs 0.625. 격차가 너무 크다 |
| 비용 | 100건당 665원 vs 790원. 싼 모델이 오히려 비싸다 |
| 캐스케이드 | Haiku 확신도 미보정으로 라우팅 불가 |

**Haiku 를 재검토할 조건**: system 블록을 4,096 토큰 이상으로 늘려 캐싱을 활성화하고
(→ 100건당 약 340원), 섀도잉 전용 사전 스크리너로 한정해 쓰는 경우.
전체 판별기로는 부적합.

## 7. 한계

1. 표본 51건, 단일 실행. Haiku 의 F1 0.625 는 신뢰구간이 넓다.

   F1 결론은 유효하나, 비용 비교는 "현재 프롬프트 길이 조건에서"라는 단서가 붙는다.
