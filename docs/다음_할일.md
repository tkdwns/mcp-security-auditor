## E. 여력이 되면 (선택 — 안 해도 포트폴리오는 완성)

효과가 큰 순서입니다.

### E-1. 럭풀(Rug Pull) 탐지 — 가장 추천
설치 후 도구 설명문이 몰래 바뀌는 공격입니다.
**1주차부터 `content_hash` 스냅샷을 쌓아 왔기 때문에 설계가 이미 끝나 있습니다.**
저장된 스냅샷을 비교해 변경분을 LLM 이 분석하면 됩니다.
"처음부터 이걸 염두에 두고 데이터 구조를 잡았다"는 이야기가 됩니다.

### E-2. 이 감사 기능을 MCP 서버로 노출
MCP 를 **쓰는** 프로젝트에서 MCP 를 **만드는** 프로젝트가 됩니다.
희소성이 크고, 무엇보다 이 프로젝트의 주제와 완벽히 맞습니다.

### E-3. scope_creep 개선 (현재 4/6)
남은 유일한 약점입니다. 같은 서버 다른 도구들의 권한 수준을 함께 제시해
비교하게 하는 방향 — 섀도잉을 고쳤던 것과 같은 접근입니다.

### E-4. GitHub Action 연동
PR 에서 MCP 설정이 바뀌면 자동 감사. 실무 적용성을 보여주기 좋습니다.
