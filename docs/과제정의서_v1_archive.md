# MCP 기반 생성형 AI 툴 연동 어시스턴트 — 과제정의서

- 작성일: 2026-08-12
- 버전: v0.1 (MVP 정의)
- 가정: ① 사용 시나리오는 "개인 생산성 통합 어시스턴트"로 설정, ② MVP 기간은 2~3주 기준. 두 가정은 3장·9장에서 쉽게 교체 가능하도록 구성했습니다.

---

## 1. 생성형 AI 판정 (발작 체크 결과: **통과, 단 조건부**)

MCP 자체는 "도구 연결 표준 프로토콜"일 뿐 생성형 AI가 아닙니다. 즉 **MCP 서버만 구현하는 프로젝트**(파일시스템 서버 만들기 등)는 인프라/백엔드 프로젝트지 생성형 AI 프로젝트가 아닙니다. 반대로 이 프로젝트가 통과하는 이유는, 중심축이 서버가 아니라 **자연어 의도를 해석하고, 어떤 도구를 어떤 순서로 쓸지 스스로 계획(planning)하고, 결과를 종합해 자연어로 생성(generation)하는 LLM 에이전트**이기 때문입니다. 이건 명백히 생성형 AI의 핵심 역량(추론+생성)입니다.

**통과 조건 (이 프로젝트를 진행할 때 반드시 지킬 것)**

- 도구 선택 로직을 `if 키워드 있으면 A도구, 없으면 B도구` 식으로 하드코딩하면 실격입니다. 반드시 LLM의 tool-use/function-calling으로 "왜 이 도구를 골랐는지"를 모델이 스스로 판단하게 하세요.
- 최소 1개는 "한 번의 질문에 여러 도구를 순차로 써야 답이 나오는" 멀티스텝 시나리오를 넣으세요. (단일 도구 1회 호출만 있으면 그냥 API 래퍼로 보입니다.)
- MCP 서버 자체 개발에 시간을 더 쓰고 싶어지는 유혹이 생길 수 있는데, 그건 확장 기능(7장)으로 미루고 MVP는 에이전트 쪽에 집중하세요.

## 2. MCP 개념 정리 (처음 접하는 사람을 위한 요약)

MCP(Model Context Protocol)는 Anthropic이 2024년 11월 공개한, LLM이 외부 도구·데이터에 붙는 방식을 표준화한 프로토콜입니다. 흔히 "AI용 USB-C"에 비유됩니다 — 도구마다 커스텀 연동 코드를 짜는 대신, 표준 규격의 케이블 하나로 이것저것 꽂아 쓰는 구조입니다.

세 주체로 이루어집니다.

- **Host**: LLM을 품고 있는 애플리케이션 (이 프로젝트에서는 우리가 만들 어시스턴트 앱)
- **Client**: Host 안에서 각 서버와 1:1 연결을 관리하는 커넥터
- **Server**: 실제 기능을 제공하는 쪽 (파일시스템, 웹 검색, Git 등)

서버는 세 가지를 노출합니다: **Tools**(모델이 호출해 실행하는 함수), **Resources**(모델이 읽을 수 있는 데이터), **Prompts**(재사용 가능한 템플릿). 통신 방식(Transport)은 로컬에서는 stdio, 원격에서는 Streamable HTTP를 씁니다. 참고로 2026-07-28 릴리스 후보 스펙에서 세션 없는(stateless) 구조와 헤더 기반 라우팅, 인증 강화(RFC 9207 기반 발급자 검증 등)가 추가되는 등 스펙이 계속 진화 중입니다.

공식 레퍼런스 서버 중 현재 활발히 유지되는 것은 **Filesystem, Fetch(웹 콘텐츠 수집), Git, Memory(지식 그래프 기반 메모리), Sequential Thinking, Time**이며, GitHub·Slack·Google Drive 등은 별도 archived 저장소로 이동된 상태입니다. 따라서 이번 프로젝트는 현재 유지보수되는 서버 위주로 조합하는 걸 권장합니다.

## 3. 문제 정의 및 시나리오 (가정 — 필요시 교체 가능)

**가정 시나리오**: 개발자나 리서처는 정보를 찾을 때 파일 탐색, 웹 검색, Git 이력 확인 등 여러 툴을 오가며 수작업으로 조사합니다. 자연어로 한 번 물어보면 에이전트가 알아서 여러 MCP 도구를 오가며 조사하고, 결과를 종합해 답해주는 비서가 있으면 이 과정이 크게 줄어듭니다.

**타겟 사용자**: 개발자/리서처 (본인이 직접 사용하며 dogfooding 하기 좋은 주제이기도 합니다).

다른 도메인(법률 문서 검색, 사내 지식 통합 등)으로 바꾸고 싶으면 3장만 교체하면 나머지 구조는 그대로 재사용 가능합니다.

---

## 4. 목표 및 성공 기준

**MVP 목표**: 자연어 질의를 받아 2개 이상의 MCP 서버에 연결된 도구를 LLM이 스스로 선택·실행하고, 결과를 종합해 답변을 생성하는 에이전트를 배포까지 완성한다.

**성공 기준**
- 준비한 테스트 시나리오(10장 참고)에서 도구 선택 정확도 80% 이상
- 멀티스텝 시나리오(도구 2개 이상 연쇄 호출) 최소 1건 정상 동작
- 배포된 데모 링크로 실제 대화 가능

## 5. 시스템 아키텍처

```
[사용자] --자연어 질의--> [Host 앱: Chat UI (CLI 또는 웹)]
                                    |
                        [MCP Client + LLM Agent]
                (Claude/GPT API — Tool Use / Reasoning / Planning)
                                    |
        --------------------------------------------------------
        |                        |                             |
 [MCP Server: Filesystem]  [MCP Server: Fetch]           [MCP Server: Git]
   (로컬 파일 검색)         (웹 콘텐츠 수집)              (레포 이력 조회)
```

동작 흐름: 사용자 질의 수신 → 에이전트가 `tools/list`로 사용 가능한 도구 목록 확인 → 질의 의도 분석 및 실행 계획 수립 → 필요한 도구를 순차/병렬로 호출 → 결과 취합 → 자연어 응답 생성 → 어떤 도구를 왜 썼는지 로그 기록.

## 6. 기능 요구사항 — MVP (2~3주 기준)

- [ ] 자연어 질의 인터페이스 (CLI 우선, 여유 있으면 간단한 웹 챗 UI)
- [ ] LLM 기반 에이전트: 사용자 의도 파악 → MCP 도구 자동 선택 (하드코딩 금지, tool-use 기반)
- [ ] MCP 서버 최소 2개 연동 (권장: Filesystem + Fetch)
- [ ] 멀티스텝 실행 시나리오 최소 1개 구현 — 예) "내 프로젝트 폴더에서 README 찾아 요약하고, 관련 최신 정보도 웹에서 찾아줘"
- [ ] 결과 종합 후 자연어 답변 생성
- [ ] 실행 로그 기록 (어떤 도구를 왜 호출했는지 — 평가·디버깅용)

## 7. 기능 요구사항 — 확장 (여유 있을 때)

- [ ] Memory 서버 추가해 대화 맥락 유지
- [ ] 사용자 승인이 필요한 액션에 대한 확인 흐름 구현 (2026-07-28 스펙의 Multi-Round-Trip 패턴 참고)
- [ ] 웹 UI 고도화 (스트리밍 응답, 도구 실행 과정 시각화)
- [ ] 자체 MCP 서버 직접 구현 (예: 개인 노션/캘린더 연동) — 여력이 되면 "MCP 서버 개발 경험"까지 포트폴리오에 추가해 희소성을 더 높일 수 있습니다

## 8. 기술 스택 (제안)

| 영역 | 제안 |
|---|---|
| LLM | Claude API (Tool Use) 또는 OpenAI API |
| MCP 연동 | Python MCP SDK |
| 백엔드 | FastAPI (백엔드 경험 보강 목적) |
| MCP 서버 | 공식 레퍼런스 서버 (Filesystem, Fetch, Git, Memory) |
| 배포 | Docker + Render/Fly.io 등 저비용 티어 |

---

## 9. 일정 (3주 예시 — 실제 가용 기간에 맞춰 조정)

1주차: MCP 개념 학습 + 공식 서버 로컬 연동 테스트(stdio) + 단순 tool-call 데모 완성
2주차: LLM 에이전트 로직 구현(의도파악→도구선택→실행→종합) + 멀티스텝 시나리오 구현
3주차: UI 연결, 로깅/평가 지표 추가, 배포, README·아키텍처 다이어그램 정리

---

## 10. 평가 계획

- 테스트 시나리오 10~15개 작성: 단일 도구 호출 5개, 멀티스텝 5개, 실패/예외 케이스 5개
- 측정 지표: 도구 선택 정확도, 응답 정확도(사람이 채점), 평균 응답 시간
- 결과를 표로 정리해 README에 포함 — "작동만 함"이 아니라 "측정했음"을 보여주는 것이 핵심
